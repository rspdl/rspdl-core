# E02 — 사내 교육 수료 문서 발급·정정 데스크

교육 운영자가 외부 교육기관의 확정 판정을 확인하고 수료 문서를 발급하며, 이름 정정과 전달 접수를 처리하는 작은 사내 업무 도구를 설계한다. 아래 요구사항을 하나의 연결된 제품 명세로 작성한다. 화면, 데이터, 행동, 권한, 조건별 결과와 데이터 출처가 서로 연결되어 있어야 한다. 산출물은 사람이 검토할 수 있는 제품 명세이며 구현 코드나 실행 결과 보고서는 필요하지 않다.

## 업무의 전제와 용어

- **E02-R01.** 제품은 교육회차 확인 → 수료판정 확인 → 최초 발급 → 발급내역 조회, 그리고 정정 요청 → 정정 발급 → 재조회, 알림 확인 → 전달 접수 → 접수 조회까지 다룬다. 출석 수집, 인원 제한, 출석률 계산, PDF 생성, 실제 메일 발송은 범위 밖이다.
- **E02-R02.** 닫힌 선택값은 다음과 같다. 수료판정값 = `수료 / 미수료 / 검토중`, 발급종류 = `최초 / 정정`, 접수선택 = `접수 / 취소`, 정정결정 = `승인 / 반려 / 보류`, 알림선택 = `통지 / 생략`, 전달선택 = `요청 / 보류`. 서로 다른 선택값 집합을 혼용하지 않는다.
- **E02-R03.** 교육회차·수강자·수료판정은 업무 시작 전에 외부 교육기관이 제공하는 기존 레코드다. 외부 호출자는 선택된 교육회차·수강자·판정이 같은 교육 이력에 속하도록 제공하며, 최초 발급의 수료판정값과 정정 발급의 정정결정도 신뢰할 수 있는 외부 결정값으로 직접 제공한다. 제품이 이를 출석 자료에서 도출하거나 레코드 간 대조로 검증하지 않는다. 기존 레코드를 행동 입력으로 넘길 수 있다는 사실과 그 필드가 화면 업무에서 조회·확보되었다는 사실은 구분한다.

## 데이터 사전

다음 일곱 종류의 레코드를 사용한다. 표의 필드는 모두 필수다. 식별번호·이름·연락처·문구는 문자열이며 날짜는 달력 날짜다.

| 요구사항 | 레코드 | 필드 |
|---|---|---|
| **E02-R04** | 교육회차 | 교육코드, 교육명, 시작일: 날짜, 종료일: 날짜 |
| **E02-R05** | 수강자 | 사번, 이름, 연락처 |
| **E02-R06** | 수료판정 | 판정번호, 결과: 수료판정값, 판정일: 날짜 |
| **E02-R07** | 발급문서 | 문서번호, 표시이름, 교육명, 발급일: 날짜, 종류: 발급종류, 제목, 본문 |
| **E02-R08** | 정정요청 | 요청번호, 원문서번호, 수정이름, 사유, 접수일: 날짜, 희망처리일: 날짜 |
| **E02-R09** | 알림 | 문서번호, 표시이름, 연락처, 제목, 내용 |
| **E02-R10** | 전달접수 | 접수번호, 문서번호, 연락처, 요청일: 날짜, 전달희망일: 날짜 |

- **E02-R11.** 같은 레코드 안에서 교육회차의 종료일은 시작일 이상, 정정요청의 희망처리일은 접수일 이상, 전달접수의 전달희망일은 요청일 이상이어야 한다. 당일 종료·당일 처리·당일 전달 희망은 허용한다. 서로 다른 레코드의 날짜를 비교하거나 오늘 날짜를 자동 적용하지 않는다.
- **E02-R12.** 발급문서는 수료판정 하나와 수신 수강자 하나를 반드시 가진다. 정정요청은 정정 대상 발급문서 하나를 반드시 가진다. 알림은 대상 발급문서 하나와 수신 수강자 하나를 반드시 가진다. 전달접수는 대상 알림 하나를 반드시 가진다. 각 관계는 앞에 적힌 레코드에서 뒤의 레코드로 향하며 각 앞 레코드에 대상이 정확히 하나다. 서로 다른 문서나 알림이 같은 수강자·문서를 가리킬 수 있다.

## 역할, 화면과 행동

- **E02-R13.** 역할은 `교육담당`과 `감사열람자`다. 교육담당은 아래 열 가지 행동을 수행할 수 있다. 감사열람자는 여섯 조회 행동만 수행할 수 있으며 수료 발급·정정 요청 접수·정정 발급·전달 접수는 수행할 수 없다. 허용과 금지를 해당 행동 및 대상 레코드에 명확하게 연결한다. 담당자 소유 여부에 따른 조건부 권한은 없다.
- **E02-R14.** 화면은 아래 여덟 개다. 각 화면은 제목, 관련 필드 입력 또는 목록·조회 영역, 행동 버튼을 가진다. 각 버튼과 화면은 다른 요소와 구별되는 식별자를 가지며 실제 행동과 연결한다. 교육·판정 확인, 수료 발급, 정정 요청, 정정 처리, 알림함, 전달 데스크는 교육담당 화면이다. 발급내역과 업무 완료는 두 역할이 접근할 수 있다.

| 화면 | 필수 내용·버튼 |
|---|---|
| 교육·판정 확인 | 교육 정보와 판정 정보 조회, 교육 조회·판정 조회, 수료 발급으로 이동, 정정 요청으로 이동 |
| 수료 발급 | 선택한 수강자·교육·판정 확인, 문서번호·발급일 입력, 수료 발급 |
| 발급내역 | 발급문서 조회, 문서 조회, 업무 완료로 진행하는 조회 성공 결과 |
| 정정 요청 | 원문서 확인, 요청번호·수정이름·사유·접수일·희망처리일 입력, 정정 요청 접수 |
| 정정 처리 | 요청 조회, 원문서·결정 확인, 새 문서번호·발급일 입력, 정정요청 조회·정정 발급 |
| 알림함 | 알림 목록과 내용, 알림 조회 |
| 전달 데스크 | 확보한 알림 확인, 접수번호·요청일·전달희망일 입력, 전달 접수·전달 조회 |
| 업무 완료 | 완료 안내, 발급내역으로 돌아가는 경로(두 역할), 알림함으로 돌아가는 경로(교육담당만) |

- **E02-R15.** 행동의 입력 계약은 다음 표와 같다. `기존`은 명시적으로 선택해 전달하는 기존 레코드 입력이고, 날짜·문자열·선택값은 별도 타입 입력이다. 관계를 따라 다른 레코드를 자동 검색하지 않는다. 조회는 그 행동에 전달한 기존 레코드의 표에 적힌 필드만 읽는다.

| 행동 | 명시적 입력 | 조회 또는 처리 대상 |
|---|---|---|
| 교육 조회 | 기존 교육회차 | 교육회차의 모든 필드 조회 |
| 판정 조회 | 기존 수료판정 | 수료판정의 모든 필드 조회 |
| 수료 발급 | 기존 교육회차·수강자·수료판정, 수료판정값, 문서번호: 문자열, 발급일: 날짜 | 발급문서 생성 여부 결정 |
| 문서 조회 | 기존 발급문서 | 발급문서의 모든 필드 조회 |
| 정정 요청 접수 | 기존 발급문서, 접수선택, 요청번호·수정이름·사유: 문자열, 접수일·희망처리일: 날짜 | 정정요청 생성 여부 결정 |
| 정정요청 조회 | 기존 정정요청 | 정정요청의 모든 필드 조회 |
| 정정 발급 | 기존 정정요청·발급문서·수료판정·수강자, 정정결정, 새 문서번호: 문자열, 발급일: 날짜 | 새 발급문서 생성 여부 결정 |
| 알림 조회 | 기존 알림 | 알림의 모든 필드 조회 |
| 전달 접수 | 기존 알림, 전달선택, 접수번호: 문자열, 요청일·전달희망일: 날짜 | 전달접수 생성 여부 결정 |
| 전달 조회 | 기존 전달접수 | 전달접수의 모든 필드 조회 |

- **E02-R16.** 외부 호출자는 정정 발급의 원문서·요청·판정·수강자와 알림 생성의 문서·수강자를 업무상 일치하는 묶음으로 제공한다. 각 행동·사건은 필요한 기존 레코드를 직접 입력받아 사용한다. 원문서 관계나 문서번호 문자열만으로 다른 입력을 찾아낸 것으로 취급하지 않는다.
- **E02-R17.** 여섯 조회 행동에는 `찾음`, `없음`, `시간초과` 결과가 있다. 찾음일 때 해당 입력 레코드의 조회 필드를 확보한다. 입력칸이나 조회 영역이 화면에 있다는 사실만으로 조회 결과를 확보하지 않는다. 없음·시간초과는 해당 조회 필드를 새로 확보하지 않는다.
- **E02-R18.** 교육 조회의 찾음은 교육·판정 확인 화면에서 정보를 표시하고, 판정 조회의 찾음은 수료 발급 화면으로, 문서 조회의 찾음은 업무 완료로, 정정요청 조회의 찾음은 정정 처리 화면에서 정보를 표시하고, 알림 조회의 찾음은 전달 데스크로, 전달 조회의 찾음은 업무 완료로 이어진다. 조회 없음은 같은 화면 메시지와 같은 조회의 재시도를, 시간초과는 같은 화면 팝업과 같은 조회의 재시도를 제공한다. 재시도는 해당 결과를 낸 버튼과 연결한다.

## 발급과 정정

- **E02-R19.** 수료 발급은 직접 받은 수료판정값이 수료일 때 발급문서 하나를 만들고, 미수료와 검토중일 때 각각 만들지 않는다. 두 미발급 상태의 설명을 구별해 수료 발급 화면에 표시한다.
- **E02-R20.** 최초 발급문서의 문서번호·발급일은 수료 발급의 동명 타입 입력에서, 표시이름은 입력 수강자의 이름에서, 교육명은 입력 교육회차의 교육명에서 가져온다. 종류는 최초로 기록한다.
- **E02-R21.** 최초 발급과 정정 발급의 발급문서 제목은 정확히 `{교육명} 수료 확인`, 본문은 정확히 `{표시이름}님 / {교육명} / {문서번호}` 형식으로 조합한다. 중괄호 안은 그 새 발급문서 안에 기록된 문자열 필드를 뜻한다. 날짜·선택값이나 입력 레코드 경로를 문구 안에서 변환하지 않는다.
- **E02-R22.** 최초 발급문서는 수료 발급이 직접 받은 수료판정과 수강자에 연결한다. 발급 성공은 발급내역으로 이어지고 새 문서를 문서 조회로 확인할 수 있다.
- **E02-R23.** 정정 요청 접수는 접수선택이 접수이면 정정요청 하나를 만들고 취소이면 만들지 않는다. 접수 성공은 정정 처리 화면으로, 취소는 정정 요청 화면의 취소 안내로 이어진다.
- **E02-R24.** 정정요청의 요청번호·수정이름·사유·접수일·희망처리일은 접수 행동의 동명 입력에서, 원문서번호는 입력 발급문서의 문서번호에서 가져온다. 대상 관계는 그 입력 발급문서에 연결한다.
- **E02-R25.** 정정 처리에서는 요청 조회로 확보한 정정요청과 조회한 원문서를 확인한다. 정정 발급은 직접 받은 정정결정이 승인일 때 새 발급문서 하나를 만들고, 반려와 보류일 때 각각 만들지 않는다. 각 미발급 결과는 정정 처리 화면에서 구별해 안내한다.
- **E02-R26.** 정정 발급문서의 문서번호·발급일은 새 문서번호·발급일 입력에서, 표시이름은 입력 정정요청의 수정이름에서, 교육명은 입력 원문서의 교육명에서 가져온다. 종류는 정정이다. 제목·본문은 E02-R21의 새 출력 필드 조합을 사용한다.
- **E02-R27.** 정정 발급문서는 정정 발급이 직접 받은 판정과 수강자에 연결한다. 원문서와 정정요청을 수정하거나 삭제하지 않는다. 성공 시 발급내역으로 이어져 새 문서를 다시 조회한다. 정정이 원문서의 유효성이나 폐기를 자동 변경한다는 정책은 없다.

## 알림과 전달 접수

- **E02-R28.** 외부의 `알림 요청 수신` 사건은 불변 입력으로 알림선택, 알림제목: 문자열, 기존 발급문서, 기존 수강자를 전달한다. 최초 문서와 정정 문서 모두 같은 계약을 사용한다. 이 사건은 발급 행동의 자동 실행 결과로 가정하지 않으며, 외부가 별도로 공급한다.
- **E02-R29.** 알림 요청 수신의 알림선택이 통지이면 알림 하나를 만들고 생략이면 만들지 않는다. 어느 선택도 빠뜨리지 않는다.
- **E02-R30.** 생성 알림의 문서번호·표시이름은 사건이 담은 발급문서의 동명 필드에서, 연락처는 사건이 담은 수강자의 연락처에서, 제목은 사건의 알림제목에서 가져온다. 내용은 새 알림의 문자열 필드만으로 정확히 `[{제목}] {표시이름}님, 문서 {문서번호}가 준비되었습니다.`를 조합한다.
- **E02-R31.** 생성 알림의 문서와 수신자 관계는 사건이 직접 담은 발급문서와 수강자에 연결한다. 사건 입력은 수정하지 않는다. 알림 생성은 외부 전달 성공을 뜻하지 않는다.
- **E02-R32.** 전달 접수는 직접 받은 전달선택이 요청이면 전달접수 하나를 만들고 보류이면 만들지 않는다. 요청 성공은 전달 데스크의 접수 완료 안내와 전달 조회로 이어지고, 보류는 같은 화면의 보류 안내로 이어진다.
- **E02-R33.** 전달접수의 접수번호·요청일·전달희망일은 동명 행동 입력에서, 문서번호·연락처는 입력 알림의 동명 필드에서 가져온다. 대상 알림 관계는 바로 그 입력 알림에 연결한다. 발급문서나 수강자를 추가로 찾아서 값을 보충하지 않는다.
- **E02-R34.** 전달 조회의 찾음은 접수 레코드를 확보해 업무 완료로 진행한다. 전달접수는 외부 발송을 위한 내부 요청의 기록이며 실제 수신, 메일 성공, 자동 재시도, 중복 제거, 예약 시각 실행을 보장하지 않는다.

## 업무 연결과 완료 기준

- **E02-R35.** 최초 발급 업무는 교육·판정 확인에서 시작한다. 교육 조회·판정 조회를 거쳐 수료 발급, 발급내역, 문서 조회, 업무 완료로 연결한다. 시작 시 외부에서 확보된 필드는 선택 수강자의 사번·이름·연락처뿐이다. 교육회차와 수료판정은 기존 레코드 참조를 제공받되 그 필드는 각 조회의 찾음에서 확보한다. 완료에는 발급문서의 문서번호·표시이름·교육명·본문 확보가 필요하다.
- **E02-R36.** 정정 업무는 정정 요청 화면에서 시작한다. 이 업무의 시작 전 외부에서 원문서를 조회해 원문서의 모든 필드와 수강자의 사번·이름·연락처를 이미 확보했다는 사전조건을 명시한다. 요청 접수 → 정정 처리의 요청 조회 → 정정 발급 → 발급내역의 새 문서 조회 → 업무 완료로 연결한다. 완료에는 새 발급문서의 문서번호·표시이름·교육명·본문이 필요하다.
- **E02-R37.** 전달 업무는 알림함에서 시작한다. 알림 레코드 참조는 외부가 제공하지만 필드는 알림 조회의 찾음에서 확보한다. 알림 조회 → 전달 데스크의 전달 접수 → 전달 조회 → 업무 완료로 연결한다. 완료에는 전달접수의 접수번호·문서번호·연락처 확보가 필요하다.
- **E02-R38.** 감사 열람 업무는 발급내역에서 시작한다. 외부가 제공한 기존 문서 참조에 대해 문서 조회의 찾음으로 문서번호·표시이름·교육명·본문을 확보한 뒤 업무 완료로 진행한다. 발급이나 정정 행동을 거칠 필요는 없다.
- **E02-R39.** 네 생성 행동에는 생성됨, 생성하지 않음, 처리실패, 시간초과 결과를 표시한다. 생성하지 않음은 해당 선택값의 안내로 처리한다. 처리실패는 원래 입력 화면의 오류 메시지와 같은 행동 재시도, 시간초과는 원래 화면의 팝업과 같은 행동 재시도를 제공한다. 실패·시간초과·취소·미생성만으로 새 레코드가 확보되었다고 보지 않는다. 재시도는 외부 처리의 중복 방지를 보장한다는 뜻이 아니다.
- **E02-R40.** 입력 필드는 해당 제출 행동과 연결한다. 완료 이동 버튼이나 화면 방문만으로 입력·조회·생성 필드를 확보했다고 표시하지 않는다. 생성한 레코드의 필드를 완료에 쓰는 업무는 명시된 재조회 성공을 거친다.
- **E02-R41.** 화면 간 경로, 각 결과의 표시·재시도, 시작 사전데이터와 완료 필수데이터를 함께 작성한다. 화면 경로에 붙인 설명만으로 수료판정·정정결정·알림선택·전달선택의 생성 정책을 대신하지 않는다.
- **E02-R42.** 교육회차·수강자·판정의 외부 공급과 알림 사건의 외부 공급을 제외하면 새 데이터는 위에 정한 생성 행동·사건에서만 생긴다. 모든 선택값의 생성 또는 미생성 결정, 필수 출력 필드의 출처와 필수 관계 연결을 명시한다. 현재 제품 범위에 없는 자동 검증·계산·전송을 추가하지 않는다.
