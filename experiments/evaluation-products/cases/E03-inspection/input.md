# E03 — 시설 점검 보고서 등록·정정·인계

동네 공공시설을 관리하는 소규모 행정팀의 업무 명세를 작성해 주세요. 담당자가 점검 보고서를 등록·제출하고, 검토자가 정정을 요청하고 담당자가 반영하거나 검토자가 반려한 뒤 인수자에게 인계하는 하나의 제품입니다. 아래 결정들을 보존한 한국어 제품 명세가 필요합니다. 화면만 나열하지 말고 데이터가 어디서 들어오고 어느 행동이 어떤 기존 기록을 읽거나 바꾸는지 연결해 주세요. 표현 범위 밖의 사항은 별도 설명으로 남겨 주세요.

## 사용자와 데이터

- **E03-R01** 역할은 점검담당자, 검토담당자, 인수담당자, 일반조회자다. 역할은 업무 권한을 뜻하며 개인별 담당 시설이나 기록 소유권은 없다.
- **E03-R02** 시설은 시설코드·시설명(문자열), 운영중(불리언)을 가진다. 모두 필수다. 시설은 외부 시설대장에서 공급되며 이 제품에서는 생성·수정·삭제하지 않는다.
- **E03-R03** 점검 보고서는 보고서번호·시설코드·시설명·작성부서·본문(문자열), 점검일·작성일(날짜), 결과(이상없음/보수필요), 상태(초안/제출/정정대기/인계완료), 열람제한(불리언)을 가진다. 모두 필수다. 시설명은 등록 당시 전달받은 명칭을 저장한다.
- **E03-R04** 정정 요청은 요청번호·보고서번호·사유·회신(문자열), 요청일(날짜), 요청종류(오기정정/내용보완), 상태(대기/반영/반려)를 가진다. 모두 필수다. 새 요청의 상태는 대기, 회신은 문자열 "미처리"다.
- **E03-R05** 인계증은 인계번호·보고서번호·받는부서·접수메모(문자열), 인계일·회신기한(날짜), 인계방식(부서전달/기록보관), 상태(초안/발행/접수)를 가진다. 모두 필수다. 준비 생성 시 상태는 초안, 접수메모는 문자열 "미접수"다.
- **E03-R06** 전송 접수 자료는 접수번호·보고서번호·수신처(문자열), 접수일(날짜)을 가진다. 모두 필수다. 외부 전송 시스템이 사건에 넣어 주는 기존 자료이며 이 제품에서 만들거나 변경하지 않는다.
- **E03-R07** 접수 안내는 접수번호·보고서번호·수신처·안내문(문자열), 처리결과(수신/거절)를 가진다. 모두 필수다. 외부 사건으로 생성되는 내부 안내 기록이다.
- **E03-R08** 보고서의 작성일은 점검일과 같거나 나중이어야 한다. 같은 날 점검·작성은 정상이다.
- **E03-R09** 인계증의 회신기한은 인계일보다 반드시 나중이어야 한다. 같은 날짜는 허용하지 않는다.
- **E03-R10** 업무 호출자는 운영중인 시설만 선택 대상으로 공급하고, 행동에 전달할 기존 기록도 미리 공급한다. 운영중인지 판정하는 것은 외부 시설대장의 책임이며 이 제품에서 판정 결과를 검증하지 않는다. 예를 들어 시설 F-17/서안체육관/운영중 참은 외부 초기 자료다. 이 전제는 외부 자료의 실제 존재·조회 성공을 제품이 증명한다는 뜻이 아니다. 화면에서 시설을 새로 만들도록 바꾸면 안 된다.
- **E03-R11** 기존 기록 대상은 매 행동의 이름 있는 입력으로 명시한다. 보고서번호가 같은 정정 요청이나 인계증을 자동 검색하지 않는다. 두 기록의 보고서번호를 비교해야 하는 곳은 아래에 명시한다. 코드 문자열은 관계나 소유권을 뜻하지 않는다.

## 행동과 처리 규칙

다음 행동의 입력·행위자·조건·읽기와 변경 내용을 연결해 주세요. 조건에 맞지 않는 경우의 금지도 명시해 주세요. 각 변경은 허용 여부와 별도로 실제로 **시도할 변경 의도**를 갖습니다.

- **E03-R12** `초안 등록`: 점검담당자가 기존 시설, 보고서번호, 작성부서, 본문, 점검일, 작성일, 결과, 열람제한을 입력한다. 등록은 이 역할에 허용하며 선택 시설의 운영 여부에 따른 별도 생성 분기를 두지 않는다. 운영중 시설 공급은 R10의 외부 전제다. 결과가 이상없음인 경우와 보수필요인 경우 각각 보고서를 하나 생성하며, 결과를 이유로 생성을 생략하지 않는다. 시설코드·시설명은 선택 시설, 나머지 값은 입력, 상태는 초안에서 온다. 시설은 읽기만 한다.
- **E03-R13** `보고서 조회`: 기존 보고서를 입력받는다. 점검담당자와 검토담당자는 상태·열람제한과 관계없이 이 기록을 읽을 수 있다. 조회가 기록을 변경하지 않는다. 일반조회자의 별도 조건은 R23과 같다.
- **E03-R14** `초안 수정`: 점검담당자가 기존 보고서와 새 본문·점검일·작성일·결과·열람제한을 입력한다. 초안일 때만 허용하고 그 밖의 상태에서는 금지한다. 허용 조건에서 대상 보고서를 읽고 위 다섯 필드를 입력값으로 바꾸는 시도를 명시한다. 번호·시설 정보·작성부서·상태를 바꾸지 않는다.
- **E03-R15** `초안 삭제`: 점검담당자가 기존 보고서를 입력한다. 초안일 때만 삭제를 허용하고 그 밖의 상태에서는 금지한다. 조건에 맞는 대상 하나를 삭제하는 시도를 명시한다. 이 삭제 처리에 같은 대상의 조회나 수정을 함께 넣지 않는다.
- **E03-R16** `보고서 제출`: 점검담당자가 기존 보고서를 입력한다. 초안일 때만 허용하고 그 밖에서는 금지한다. 대상 보고서를 읽고 상태를 제출로 바꾸는 시도를 명시한다. 본문이나 날짜를 다시 입력시키지 않는다.
- **E03-R17** `정정 요청 등록`: 검토담당자가 기존 보고서, 요청번호, 요청일, 사유, 요청종류를 입력한다. 이 역할의 요청 준비 등록을 허용하며 보고서 상태에 따른 생성 분기는 두지 않는다. 보고서를 읽고 요청종류가 오기정정인 경우와 내용보완인 경우 각각 정정 요청 하나를 생성한다. 어느 종류도 생성을 생략하지 않는다. 보고서 상태는 이 행동에서 바꾸지 않는다. 정정 업무를 개시하는 별도 행동은 R41과 같다. 요청의 보고서번호는 선택 보고서에서, 다른 값은 입력 및 R04의 초기값에서 온다.
- **E03-R18** `정정 반영`: 점검담당자가 기존 보고서, 기존 정정 요청, 새 본문·결과·회신을 입력한다. 보고서가 정정대기이고 요청이 대기이며 두 기록의 보고서번호가 같을 때에만 허용한다. 이 중 하나라도 맞지 않으면 금지한다. 두 기록을 읽고 보고서의 본문·결과·상태(제출), 요청의 상태(반영)·회신을 바꾸는 시도를 명시한다. 요청을 삭제하거나 새 보고서로 대체하지 않는다.
- **E03-R19** `정정 반려`: 검토담당자가 기존 보고서, 기존 정정 요청, 회신을 입력한다. R18과 같은 세 가지 기존 기록 조건에서만 허용하고 그렇지 않으면 금지한다. 두 기록을 읽고 보고서 상태를 제출, 요청 상태를 반려, 회신을 입력값으로 바꾸는 시도를 명시한다. 보고서 본문·결과는 바꾸지 않는다.
- **E03-R20** `인계증 발행`: 검토담당자가 기존 보고서, 인계번호, 받는부서, 인계일, 회신기한, 인계방식을 입력한다. 이 역할의 인계증 준비 생성을 허용하며 보고서 상태에 따른 생성 분기는 두지 않는다. 보고서를 읽고 인계방식이 부서전달인 경우와 기록보관인 경우 각각 초안 인계증 하나를 생성한다. 어느 방식도 생성을 생략하지 않는다. 이 단계에서 보고서 상태를 바꾸지 않으며 실제 인계 확정은 R42의 별도 행동이다. 인계증의 보고서번호는 선택 보고서에서, 나머지는 입력 및 R05의 초기값에서 온다.
- **E03-R21** `인계 조회`: 검토담당자와 인수담당자가 명시적으로 입력받은 기존 인계증을 읽을 수 있다. 보고서를 따라 인계증을 찾지 않으며 조회만으로 접수하지 않는다.
- **E03-R22** `인계 접수`: 인수담당자가 기존 인계증, 회신일(날짜), 접수메모(문자열)를 입력한다. 인계증이 발행 상태이고, 회신일이 인계일 이상이며 회신기한 이하인 경우에만 허용한다. 그 밖에서는 금지한다. 인계증을 읽고 상태를 접수, 접수메모를 입력값으로 바꾸는 시도를 명시한다. 회신일은 이번 행동의 명시적 입력이며 현재 시각을 자동 사용하지 않는다. 기한 당일 회신은 허용한다.
- **E03-R23** 일반조회자의 `보고서 조회`는 열람제한이 참이 아니고, 상태가 제출 또는 인계완료인 경우에만 허용한다. 열람제한이 참이거나, 상태가 제출·인계완료 중 어느 것도 아니면 금지한다. 모든 조건/하나 이상의 조건/조건의 부정을 구분해서 이 결정을 보존한다.
- **E03-R24** 위에서 해당 행동을 허용한 역할 이외의 역할에는 그 행동을 금지한다. 예를 들어 일반조회자는 본문 수정·삭제·제출·정정·인계를 할 수 없고, 인수담당자는 보고서를 정정할 수 없다. 명시한 허용과 금지 사이에 우선순위나 묵시적 관리자 예외를 만들지 않는다.
- **E03-R25** 권한이 있다는 선언 자체가 조회·수정·삭제를 실행한 결과는 아니다. 허용/금지와 조건에 맞을 때 자동으로 시도할 읽기·필드 변경·삭제 의도를 구분한다. 생성 결과를 포함해 실제 저장 성공, 여러 기록의 일괄 성공, 재시도 성공을 약속하지 않는다.

## 외부 접수 사건

- **E03-R26** `전송 접수 통지` 사건은 외부 전송 접수 자료 하나와 직접 입력인 처리결과(수신/거절)를 담는다. 이 자료와 결과는 사건이 넘긴 그대로의 읽기 전용 입력이다. 보고서나 인계증의 현재 상태를 다시 검색해서 사건 내용을 바꾸지 않는다.
- **E03-R27** 사건이 발생하면 시스템이 전달된 전송 접수 자료를 읽는 처리를 자동으로 시도한다. 이 사건 규칙에서 자료를 수정·삭제하거나 보고서 상태를 바꾸지 않는다. 실제 외부 전송이나 인계 접수 완료를 이 읽기로 보장하지 않는다.
- **E03-R28** 처리결과가 수신이면 접수 안내 하나, 거절이어도 접수 안내 하나를 생성한다. 접수번호·보고서번호·수신처는 사건에 담긴 자료에서, 처리결과는 직접 사건 입력에서 온다. 안내문은 두 결과 모두 이미 기록한 문자열 필드를 이용해 "접수번호: 보고서번호 / 수신처" 형식으로 조합한다. 처리결과 자체는 별도 필드에서 구분한다. 두 경우 중 안내를 생략하는 경우는 없다. 보고서번호가 같다는 이유로 다른 보고서나 인계증을 변경하지 않는다.

## 여덟 화면과 업무 경로

- **E03-R29** `시설 선택 화면`: 외부에서 공급된 시설을 선택하는 시작 화면이다. 선택 버튼으로 보고서 작성 화면, 보고서 목록 버튼으로 목록 화면에 간다. 시설 공급·선택은 호출자 전제로 남기고 시설 관리 기능을 추가하지 않는다.
- **E03-R30** `보고서 작성 화면`: 보고서 생성과 보고서번호·작성부서·본문·점검일·작성일·결과·열람제한 입력을 제공한다. 시설코드·시설명은 선택 시설에서 미리 채워진다. 등록 버튼과 취소 버튼을 둔다.
- **E03-R31** `보고서 목록 화면`: 보고서번호·시설명·점검일·상태를 조회하고 선택한 보고서의 상세로 가는 열기 버튼, 시설 선택 화면으로 가는 새 보고서 버튼을 둔다. 이 목록을 실제로 어느 역할에 보여 주는지는 보고서 조회 권한을 따른다.
- **E03-R32** `보고서 상세 화면`: 보고서의 모든 필드를 조회하고 초안 수정용 다섯 필드를 입력할 수 있다. 저장·제출·삭제·정정 요청·인계 발행·목록 버튼을 둔다. 정정 요청과 접수 안내는 각각 자신의 모든 필드를 조회하는 별도 영역으로 놓고, 전달받은 정정 요청의 정정 개시 버튼과 처리 버튼도 둔다. 번호가 같다고 관련 기록을 자동 조회하지 않는다.
- **E03-R33** `정정 요청 화면`: 정정 요청 생성 및 요청번호·요청일·사유·요청종류 입력을 제공한다. 요청 버튼과 취소 버튼을 둔다. 보고서번호와 상태·회신 초기값은 R17의 출처를 따른다.
- **E03-R34** `정정 처리 화면`: 전달된 보고서·정정 요청을 조회하며 새 본문·결과·회신 입력, 반영·반려·취소 버튼을 둔다. 이 화면에 방문하는 것만으로 정정이 처리되지는 않는다.
- **E03-R35** `인계 발행 화면`: 인계증 생성 및 인계번호·받는부서·인계일·회신기한·인계방식 입력을 제공한다. 발행·취소 버튼을 둔다. 보고서번호와 상태·접수메모 초기값은 R20의 출처를 따른다.
- **E03-R36** `업무 완료 화면`: 등록한 보고서의 번호·시설명·작성부서·본문·점검일·작성일·결과·열람제한을 확인하고, 명시적으로 전달된 인계증 전체 필드를 조회할 수 있다. 전달된 초안 인계증의 인계 확정 버튼과, 인계 접수를 위한 회신일·접수메모 입력과 접수 버튼, 목록 버튼을 둔다. 등록 완료와 인계 접수 완료를 같은 상태로 혼동하지 않는다.
- **E03-R37** 경로는 시설 선택→작성→등록→업무 완료→목록→상세를 기본으로 한다. 상세에서 정정 요청→요청→상세, 상세에서 정정 처리→반영 또는 반려→상세, 상세에서 인계 발행→발행→업무 완료로 이어진다. 상세 저장·제출·정정 개시는 상세로, 삭제는 목록으로, 완료의 인계 확정·접수 버튼은 완료로 간다. 각 이동은 해당 이름의 버튼에 연결한다. 화면 이동의 조건 설명이 권한 평가를 대신하지 않는다.
- **E03-R38** `보고서 등록 완료` 업무의 시작은 시설 선택 화면, 완료는 업무 완료 화면이다. 시설의 시설코드·시설명은 호출자가 확보해 주는 초기 데이터다. 이는 외부 시설의 값이 가용하다는 전제이며 아직 보고서 레코드가 존재한다는 뜻은 아니다. 보고서 작성 화면의 등록 버튼 제출에서 보고서번호·작성부서·본문·점검일·작성일·결과·열람제한을 확보하며, 보고서의 이 일곱 값과 시설의 초기 두 값이 완료에 필요하다. 보고서에 복사되는 시설 값의 출처는 등록 행동에 따로 연결하며, 복사가 실제 수행됐다고 이 업무 선언만으로 증명하지 않는다. 입력칸의 배치와 실제 제출 지점을 연결한다. 상태 초기값은 생성 결과이며 사용자가 입력하는 값이 아니다.
- **E03-R39** 작성 취소는 시설 선택으로, 정정 요청·정정 처리·인계 발행 취소는 상세로 돌아간다. 취소가 필수 입력을 확보하거나 업무 완료로 바로 이동해서는 안 된다. 수정·제출·정정·인계 경로를 등록 완료 업무의 새 시작으로 간주하지 않는다.
- **E03-R40** 이 제품은 점검 점수 산술, 정기 점검 스케줄러, 자동 기한 감시, 소유자 판정, 관계 검색·조인, 자동 보고서번호 발급, 중복 요청 탐지, 전송 재시도, 삭제 후 복구, 트랜잭션·동시성 보장을 포함하지 않는다. 날짜 순서 규칙과 권한·변경 의도의 표현이 실제 서버의 실행·성공을 보장한다고 설명하지 않는다.

## 준비 기록의 정정 개시와 인계 확정

- **E03-R41** `정정 개시`: 검토담당자가 기존 보고서와 기존 정정 요청을 각각 입력한다. 보고서가 제출이고 요청이 대기이며 두 기록의 보고서번호가 같을 때만 허용한다. 하나라도 맞지 않으면 금지한다. 두 기록을 읽고 보고서 상태를 정정대기로 바꾸는 시도를 명시한다. 요청 등록만으로 정정대기가 되지 않으며 개시 뒤에 R18/R19의 처리를 할 수 있다.
- **E03-R42** `인계 확정`: 검토담당자가 기존 보고서와 기존 인계증을 각각 입력한다. 보고서가 제출이고 인계증이 초안이며 두 기록의 보고서번호가 같을 때만 허용한다. 하나라도 맞지 않으면 금지한다. 두 기록을 읽고 보고서는 인계완료, 인계증은 발행 상태로 바꾸는 시도를 명시한다. 초안 생성만으로 인계완료나 인수 가능 상태가 되지 않는다. 두 기록의 동시 저장 성공은 보장하지 않는다.
