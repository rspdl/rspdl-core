# E01 — 소형 수리점의 방문 접수부터 고객 인계까지

동네 소형가전 수리점에서 접수직원과 수리기사가 함께 사용하는 업무 명세를 작성해 주세요. 처음 찾아온 고객의 방문 접수와 미리 작성한 접수표를 가진 고객의 접수를 한 흐름으로 합치고, 기기 확인·점검·수리완료·고객 인계까지 빠짐없이 이어지는 제품입니다. 아래 결정은 확정된 제품 요구사항입니다. 요구사항 ID를 추적할 수 있는 중립적인 제품 명세를 결과로 주세요.

## 업무 범위와 용어

- **E01-R01** 이 제품의 범위는 고객 한 명의 기기 한 대를 접수하여 수리를 마친 뒤 창구에서 고객에게 인계하는 기록 업무다. 수리 작업 자체, 수리 불가 판정 이후 처리, 부품 재고, 비용·결제, 배송, 알림 발송은 다루지 않는다.
- **E01-R02** 접수표는 고객·기기·요청사항을 담은 원본이다. 기기확인기록은 맡긴 물품의 외관과 동봉품, 점검기록은 기사 확인 내용, 수리완료기록은 실제 작업 내용, 인계확인서는 고객에게 돌려준 사실을 담는다. 완료 화면의 인계증은 이 기록들을 보여주는 화면이며 별도 중복 저장 자료가 아니다.
- **E01-R03** 한 번의 업무에는 접수표 하나와 각 후속 기록 하나씩을 다룬다. 다음 단계에 현재 선택한 기존 기록을 명시적으로 넘긴다. 접수번호가 같다는 이유로 다른 자료를 자동 검색하거나 합치지 않는다. 여러 건 동시 처리나 다른 접수 건으로 전환하는 기능은 없다.

## 자료와 날짜

아래에서 ‘필수’는 완료 업무에 값이 있어야 한다는 뜻이다. 날짜는 시각이나 시간대가 없는 달력 날짜다.

- **E01-R04** 접수표에는 접수번호·고객명·연락처·기기명·고장설명이라는 필수 문자열과 접수일·수령희망일이라는 필수 날짜가 있다. 접수번호는 방문 고객의 종이 접수표에 이미 적힌 번호를 직원이 입력하며 자동 발번하지 않는다. 연락처는 전화번호를 담는 문자열이고 이메일로 한정하지 않는다.
- **E01-R05** 기기확인기록에는 필수 문자열인 외관확인·동봉품확인이 있다. 동봉품이 없으면 빈칸 대신 ‘없음’을 입력한다.
- **E01-R06** 점검기록에는 필수 문자열인 점검내용·조치계획이 있다. 별도 승인이나 조건별 작업 경로를 만들지 않는다.
- **E01-R07** 수리완료기록에는 필수 날짜인 작업시작일·작업완료일과 필수 문자열인 작업내용·동작확인이 있다.
- **E01-R08** 인계확인서에는 필수 문자열인 수령인명·반환물품확인과 필수 날짜인 인계일이 있다. 이 범위에서는 방문한 고객 본인이 수령하며 대리인 증빙은 다루지 않는다.
- **E01-R09** 접수표의 수령희망일은 같은 접수표의 접수일 이후 또는 같은 날이어야 한다. 희망일은 고객의 희망 사항이며 수리완료나 인계의 마감 기한이 아니다.
- **E01-R10** 수리완료기록의 작업완료일은 같은 기록의 작업시작일 이후 또는 같은 날이어야 한다. 날짜를 자동 보정하지 않는다. 다른 기록 사이의 날짜 비교, 오늘 날짜에 따른 제한, 영업일 계산은 요구하지 않는다.

## 외부 자료와 업무 시작

- **E01-R11** 이 제품에 들어오기 전에 별도 접수대장이 사전작성 접수표를 보관한다. 기존 접수 경로를 선택하면 상위 접수대장이 선택한 기존 접수표 하나를 조회 행동의 입력으로 전달한다. 접수대장의 검색·선택 화면, 외부 통신 구현과 기존 자료 작성 기능은 이 제품 밖이다. 방문 접수 경로는 이 제품 안에서 접수표를 새로 만든다.
- **E01-R12** 업무는 항상 업무시작 화면에서 시작한다. 시작 시 이미 확보되었다고 가정할 업무 필드는 없다. 기존 접수표가 외부에 있다는 사실이나 그 기록이 조회 입력으로 전달되었다는 사실만으로 고객 정보가 확보된 것은 아니다. 기존 경로에서는 조회 성공으로 받은 자료만 뒤 단계가 사용할 수 있다.

## 역할과 화면

- **E01-R13** 역할은 접수직원과 수리기사 두 가지다. 접수직원은 사전접수 조회·방문접수 제출·접수 확정·인계 확정·조회 중단·방문접수 중단을 허용하고 점검 저장·수리완료 저장은 금지한다. 수리기사는 점검 저장·수리완료 저장을 허용하고 나머지 여섯 행동은 금지한다. 담당자·작성자·접수 상태에 따라 달라지는 예외는 없다.
- **E01-R14** 화면은 업무시작, 사전접수조회, 방문접수입력, 접수확인, 점검기록, 수리완료입력, 인계확인, 인계완료의 여덟 개다. 점검기록과 수리완료입력은 수리기사 화면이고 나머지는 접수직원 화면이다. 접수확정 뒤 기사에게, 수리완료 저장 뒤 접수직원에게 같은 업무 묶음을 인계한다. 로그인·세션 전환 자체는 이 제품의 범위가 아니다.
- **E01-R15** 모든 입력은 이름이 있는 폼 항목으로, 조회 자료는 이름이 있는 조회 영역으로, 조작은 이름이 있는 버튼으로 드러내야 한다. 자료를 다루는 버튼은 수행할 행동과 사용하는 자료가 분명해야 한다. 화면 선택·전환만 하는 버튼은 이동 대상이 분명하면 된다. 오류·시간 초과 문구만 적고 사용자가 취할 조작을 빠뜨리지 않는다.

## 두 가지 접수 경로

- **E01-R16** 업무시작 화면에는 ‘사전작성 접수표 사용’과 ‘새 방문 접수’ 버튼이 있다. 각각 사전접수조회와 방문접수입력으로 이동한다. 이 선택만으로 접수가 완료되지는 않는다.
- **E01-R17** 사전접수조회 화면의 ‘사전접수 조회’ 버튼은 외부에서 선택한 기존 접수표를 입력받아 그 접수표의 모든 일곱 필드를 조회한다. 성공 결과가 이 필드들을 제공하고 접수확인 화면으로 이동한다. 이 경로에서는 접수표를 새로 만들거나 고객 정보를 다시 입력하지 않는다.
- **E01-R18** 사전접수 조회 실패는 같은 화면에 ‘접수표를 확인할 수 없습니다’를 표시한다. 같은 ‘사전접수 조회’ 버튼으로 재시도할 수 있고, 별도의 ‘새 방문 접수로 전환’ 버튼으로 방문접수입력에 갈 수 있다. 실패 결과는 접수표 필드를 제공하지 않는다.
- **E01-R19** 사전접수 조회의 시간 초과는 같은 화면의 팝업 ‘조회 응답을 확인하지 못했습니다’로 처리한다. 팝업을 닫은 뒤 이 화면의 ‘사전접수 조회’ 버튼으로 재시도할 수 있어야 한다. 시간 초과를 조회 성공으로 취급하지 않으며 경과시간을 세는 기능은 요구하지 않는다.
- **E01-R20** 사전접수조회 화면의 별도 ‘조회 중단’ 버튼은 조회 중단 행동의 취소 결과로 업무시작 화면에 돌아간다. 해당 복귀 경로를 분명히 한다. 새 접수표나 후속 기록을 만들지 않으며 인계완료로 이동하지 않는다.
- **E01-R21** 방문접수입력 화면에는 접수표의 일곱 필드가 모두 입력 항목으로 있어야 한다. ‘방문접수 제출’ 버튼에서 제출한 값으로 접수표를 새로 만들며, 성공 결과만 접수확인 화면으로 이동한다. 단순히 입력 화면에 들어온 것을 제출로 취급하지 않는다.
- **E01-R22** 방문접수 제출 실패는 같은 화면의 메시지 ‘접수표를 저장하지 못했습니다’, 시간 초과는 같은 화면의 팝업 ‘저장 응답을 확인하지 못했습니다’로 처리한다. 두 경우 모두 입력을 확인·보완하고 같은 ‘방문접수 제출’ 버튼으로 재시도할 수 있게 한다. 저장 성공이나 접수확인 도착으로 표현하지 않는다.
- **E01-R23** 방문접수입력 화면의 별도 ‘방문접수 중단’ 버튼은 방문접수 중단 행동의 취소 결과로 업무시작에 돌아간다. 해당 복귀 경로를 분명히 한다. 제출 버튼과 구별하고, 미제출 입력을 완료 업무의 자료로 쓰지 않는다. 중단은 기존 자료를 삭제하는 행동이 아니다.

## 접수확인부터 고객 인계까지

- **E01-R24** 두 접수 경로가 합쳐지는 접수확인 화면은 확보한 접수표의 일곱 필드를 조회해 보여주고, 기기확인기록의 외관확인·동봉품확인을 입력받는다. 조회 영역을 입력 필드로 간주하거나 조회에 실패한 접수표로 진행하지 않는다.
- **E01-R25** 접수확인 화면의 ‘접수 확정’ 버튼은 현재 접수표와 제출한 기기확인 값을 사용한다. 성공 시 기기확인기록을 새로 만들고 점검기록 화면으로 이동한다. 접수표를 중복 생성하지 않는다.
- **E01-R26** 점검기록 화면은 현재 접수표의 접수번호·기기명·고장설명과 기기확인기록의 두 필드를 조회한다. 점검내용·조치계획을 입력하고 ‘점검 저장’ 성공 시 점검기록을 새로 만들어 수리완료입력으로 이동한다.
- **E01-R27** 수리완료입력 화면은 현재 접수표의 접수번호·기기명과 점검기록의 두 필드를 조회한다. 수리완료기록의 네 필드를 입력하고 ‘수리완료 저장’ 성공 시 수리완료기록을 새로 만들어 인계확인으로 이동한다.
- **E01-R28** 인계확인 화면은 접수표의 일곱 필드, 기기확인기록의 두 필드, 수리완료기록의 네 필드를 조회한다. 접수직원은 수령인명·반환물품확인·인계일을 입력하고 ‘인계 확정’ 성공 시 인계확인서를 새로 만들어 인계완료로 이동한다. 고객명 표시만으로 수령인명 제출을 대신하지 않는다.
- **E01-R29** 접수 확정·점검 저장·수리완료 저장·인계 확정 각각의 실패 결과는 해당 버튼이 있는 화면의 ‘기록을 저장하지 못했습니다’ 메시지로 처리한다. 입력을 확인·보완한 뒤 바로 그 버튼으로 재시도할 수 있어야 한다. 실패에서 다음 단계로 진행하는 경로는 없다.
- **E01-R30** 같은 네 행동 각각의 시간 초과는 해당 화면의 ‘저장 응답을 확인하지 못했습니다’ 팝업으로 처리한다. 팝업을 닫은 뒤 바로 그 버튼으로 재시도할 수 있어야 한다. 다른 화면에 같은 이름의 행동이 있다는 것만으로 복구 수단을 대신하지 않는다. 실제 저장 여부를 확인하지 못한 상태를 성공이라고 표시하지 않는다.
- **E01-R31** 중간 저장 성공은 그 단계의 입력만 확보한다. 뒤 단계 필드를 앞 단계 성공 결과에 미리 포함하지 않는다. 화면 열기·조회 영역 배치·실패 문구가 새로운 기록이나 필드 값을 만드는 것은 아니다.

## 완료의 의미

- **E01-R32** 이 제품의 업무 완료는 인계완료 화면 도착 하나다. 정상 성공 경로는 업무시작 → 두 접수 경로 중 하나 → 접수확인 → 점검기록 → 수리완료입력 → 인계확인 → 인계완료다. 취소·실패·시간 초과나 단순 화면 이동으로 중간 단계를 건너뛰어 완료하는 경로를 두지 않는다.
- **E01-R33** 완료 시 반드시 확보되어야 할 자료는 접수표의 일곱 필드, 기기확인기록의 두 필드, 점검기록의 두 필드, 수리완료기록의 네 필드, 인계확인서의 세 필드 전부다. 수기 접수와 기존 접수 두 경로 모두 같은 완료 의무를 만족해야 한다.
- **E01-R34** 인계완료 화면에는 접수번호·고객명·연락처·기기명·고장설명·접수일·수령희망일, 외관확인·동봉품확인, 점검내용·조치계획, 작업시작일·작업완료일·작업내용·동작확인, 수령인명·반환물품확인·인계일을 인계증으로 조회해 보여준다. 완료 화면에 입력칸을 두어 앞서 빠뜨린 값을 나중에 채우지는 않는다.
- **E01-R35** 접수표의 외부 조회, 각 폼의 제출, 각 새 기록의 생성, 각 행동 결과, 화면 이동과 복구 수단의 연결을 명세에서 구분한다. 외부 서비스의 실제 응답, 실제 저장·재시도·사용자 인계가 실행된다는 보장이나 중복 저장 방지 기능은 이 문서의 범위가 아니다.
