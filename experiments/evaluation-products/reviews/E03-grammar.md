## Support boundaries communicated to the author

| Area | Supported expression and checks | Human judgment or unsupported behavior |
| --- | --- | --- |
| Actor and permission | Explicit System/Role actor, Action/Event trigger, direct trigger-owned typed bindings, And/Or/Not comparisons, and one Can/Cannot/DoAttempt modality are preserved in IR. Role and input references, scalar types, and local effect compatibility are checked. | Roles do not identify the current user or encode row ownership. Guard truth, cross-rule overlap/gap, priorities, authorization execution, and automatic success are not established by compilation. |
| Existing records | Action ExistingModel inputs may be Read/Update/Delete targets; assignments carry explicit field IDs and typed scalar values. | No joins, target selection from arbitrary collections, post-state execution, or implicit existing-record identity. |
| Supplied event | Event input bindings have TriggerPayload phase; a System + DoAttempt + Read statement can preserve supplied-event intent. Legacy conditional Event production supports declared enum decisions and typed field/relation producers. | Event record payloads are immutable. Update/Delete fails `RSPDL-STMT-012`; an event cannot silently become a mutable Action input. Event delivery, timing, retries, and eventual success are application semantics. |
| Runtime | Same-record field-to-field date/date-time invariants support concrete checks with strict/inclusive equality boundaries. | Unified statements have `LinkedAndTypeCheckedOnly` status. `check` emits `RSPDL-STMT-090`, and model finding returns Unsupported. Compiler success is not a successful acceptance journey. |
| Workflow | Declared start, acquisitions, completions, references, reachable completion, and field presence have checks. | Flow condition strings do not evaluate guards. Workflow analysis does not execute mutations; reachable legacy delete/conditional production may produce `RSPDL-WORKFLOW-U001`. |
| External initial data | An existing Action/Event input declaration and unified Read can link without inventing a creator. Workflow initial-data declarations seed workflow field presence. | Legacy screen reads independently demand a model creator and input-field producer (`RSPDL-DATA-001/002`). Workflow initial data and conditional producers do not repair that legacy producer analysis. Preserve expressible structured facts and record the actual diagnostics; do not invent a creation screen or grant a global diagnostic exemption. |
| Unsupported constructs | Required scalar fields, typed direct inputs, literal comparisons/assignments and local boolean groups fit the current slice. | Dynamic timers/implicit clocks, relation selectors/joins, general arithmetic, Create inside statements, and optional-field operands are outside it; optional operands fail `RSPDL-STMT-011`. |

The external-data caveat is visible in `analyze_data_usage`'s arguments and independent producer sets. The `boundary-explicit-initial-data` workflow fixture also declares creation screens, so it does not prove that external-only screen reads compile. Initial discussion suggested UI layout/prose at this bridge; the coordinating review clarified the final rule: retain currently expressible structured declarations even when they trigger known DATA diagnostics. Prose explains the missing analysis connection and does not replace an expressible fact to obtain clean compilation.
