# E03 독립 공정성 검토

검토 대상은 최신 `cases/E03-inspection/input.md`, `evaluator.md`와 공통 `public-contract.md`, `generation-protocol.md`, `judge-instructions.md`다. 다른 제품의 해설·정답 구현·생성 결과를 근거로 사용하지 않았다. 이 검토는 공개 요구와 비공개 판정의 정합성 검토이며 실제 후보 평가나 문법 실행 결과가 아니다.

## 판정

최신 수정본에서 공정성 차단 항목은 발견하지 않았다. 하나의 시설 점검 업무가 등록→제출→정정 준비/개시/처리→인계 준비/확정/접수로 연결된다. 외부 시설과 접수 자료, 내부 생성 기록, 역할별 기존 기록 변경, 화면 이동 및 취소의 책임이 공개 입력에 구별되어 있다. 산술·스케줄러·자동 검색·트랜잭션 같은 비범위를 추가하도록 강제하지 않는다.

문법 표현 가능성 자체는 별도의 소스 검토 대상이다. 이 검토는 제시된 문법 지원 설명을 실제 컴파일 성공이나 조건 공간의 안전성 증명으로 승인하지 않는다.

## 발견 후 수정 확인

| 항목 | 최초 문제 | 최신 수정본 확인 |
| --- | --- | --- |
| 반영 주체 | 서두가 검토담당자의 반영을 서술하여 R18/R24와 충돌했다. | 서두가 점검담당자 반영·검토담당자 반려로 정정되었다. |
| 양 군의 산출물 중립성 | 일부 판정 행과 표현 대안이 RSPDL 용어를 최종 명세의 필수 구문처럼 읽힐 여지가 있었다. | 판정 방식에 양 군 모두 최종 한국어 명세만 평가하고, 용어는 의미·지원 근거의 약칭이며 특정 구문을 요구하지 않고, 중간본·로그에만 있는 사실은 가점하지 않는다고 명시했다. R25도 자연어 의미로 정리되었다. |
| 준비 생성과 조건부 변경 | 이전 생성·상태 변경 구분이 수정되면서 하위 예시의 동기화가 필요했다. | R17/R20은 준비 생성, R41/R42는 두 기존 기록의 조건을 확인하는 변경 시도로 구별되며 여정 1에도 두 단계가 남아 있다. |
| 신규 직접 입력 | 요청종류·인계방식 추가가 모델·입력·화면·여정에 반영되어야 했다. | R04/R17/R33과 R05/R20/R35 및 여정 1의 생성 입력이 함께 수정되었다. 두 열거 값 모두 하나 생성하며 종류에 따른 새 거절 정책은 없다. |

## 수량과 추적 정합성

공개 요구는 R01–R42 각 1회, 평가 표도 같은 42개 ID 각 1회다. 모델은 시설·보고서·정정 요청·인계증·전송 접수 자료·접수 안내의 6개, 화면은 8개, 이름 있는 업무 행동은 13개다. 사건은 업무 행동과 별도로 기술되어 있다.

| 대상 | 최신 공개 입력과 평가표의 수량 |
| --- | --- |
| 시설 / 보고서 / 요청 / 인계증 / 접수 자료 / 안내 필드 | 3 / 10 / 7 / 8 / 4 / 5 |
| 보고서 등록 직접 입력 / 초안 수정 입력 | 7 / 5 |
| 요청 화면 직접 입력 / 인계 발행 화면 직접 입력 | 4 / 5 |
| 등록 완료 화면의 보고서 조회 필드 | 8 |
| 등록 완료 업무의 필수 데이터 | 외부 시설 2개 + 등록으로 확보하는 보고서 7개 = 9개 |

완료 화면의 조회 필드 8개와 완료 업무의 가용성 요구 9개는 서로 다른 계약이다. 평가표는 이를 혼동하지 않는다. 작성부서는 생성·입력·확보·완료 조회에 남아 있으며 초안 수정 대상에는 들어가지 않는다. 상세의 기본 여섯 버튼과 별도 요청 영역의 정정 개시·처리 버튼도 누락 없이 서술된다.

## 세 사람용 여정 대조

| 여정 | 공개 요구와의 대조 |
| --- | --- |
| 체육관 보고서를 등록하고 정정 후 인계하기 | 같은 날 점검·작성 허용, 요청종류=내용보완, 준비 요청→정정 개시→담당자 반영, 인계방식=부서전달, 초안 생성→인계 확정→기한 당일 접수, 사건 수신 안내의 출처가 공개 정책과 일치한다. |
| 잘못 전달된 정정 요청을 되돌리고 반려하기 | 번호 불일치 금지 후 호출자가 올바른 요청을 별도 공급한다. 반려는 본문·결과를 변경하지 않는다. 초안 수정 다섯 필드와 단독 삭제, 거절 사건의 안내문 `RC-92: IR-2402 / 운영팀 외부함`도 입력과 일치한다. |
| 날짜 경계·제한 공개·취소 우회를 놓치지 않기 | 날짜의 엄격/포함 경계, 일반조회자의 AND/OR/부정, 검토담당자의 무조건 보고서 조회, 접수 재시도 금지, 취소 미획득, 외부 운영 판정 전제가 공개 정책과 일치한다. 인계방식=기록보관에도 별도 접수 금지 조건을 만들지 않는다. |

세 제목과 본문은 문서를 사람이 따라 읽는 보조 검토다. 실제 저장·실행·롤백·외부 시스템 가동이나 권한 truth table 실행을 요구하지 않는다. 여정은 요구사항 분모에 더해지지 않으며 전체 42개 요구의 판정을 대신하지 않는다.

## 공정성 경계

- 문자열 식별자에서 자동 관계·소유권·유일성·중복 탐지를 추론하지 않는다. 두 기록의 번호 일치는 공개적으로 요구된 행동에서 확인한다.
- 운영중 시설 공급과 기존 기록 공급은 외부 전제다. 운영중=false 입력으로 내부 생성 거절 기능을 요구하거나 외부 데이터를 만들도록 강제하지 않는다.
- 종류별 동일 생성 결과는 공개 입력에 있다. 최종 자연어 명세가 두 종류 모두 하나 생성한다는 동등한 의미를 보존하면 구문별 분기나 특정 RSPDL 표현을 강제할 근거가 없다.
- 사건의 수신·거절은 동일한 문자열 조합 형식과 별도 처리결과 필드로 구분한다. 숨은 결과별 문구나 추가 복구·재전송 정책은 없다.
- 제한된 문법 표현과 분석의 unknown 설명은 허용하되, 최종 명세의 필드 출처·버튼 연결·역할·조건 누락을 중간 RSPDL이나 도구 진단으로 보충하지 않는다.
- 공통 절차가 동일 호출 수·모델 설정·출력 상한, 추가 입력 비용 공개, 불투명 후보 평가, 사람 재검토 및 입력 오류 발생 시 양 군 재평가를 요구한다. 실제 실험 실행 여부·난이도·성능·점수에 관한 결론은 이 검토에서 내리지 않았다.
