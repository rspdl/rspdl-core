# E02 독립 공정성 검토

검토 역할: 작성·문법 검토와 분리된 fresh-context Sol 6.1 계열 평가자. 검토 대상은 E02 `input.md`, `evaluator.md`, 공통 `public-contract.md`, `generation-protocol.md`, `judge-instructions.md`다. 실제 후보 출력·점수·실행 결과는 제공받지 않았다. 이 문서는 평가 설계 검토이며 경험적으로 난도나 성능을 검증한 결과가 아니다. 소유 범위는 이 검토 파일뿐이다.

## 결론

42개 공개 요구 ID가 비공개 증거표에 정확히 한 번씩 대응한다. 세 여정은 한 제품의 최초 발급·정정·감사·알림·전달·미생성·복구를 설명하며 별도 생성 프롬프트나 실행 테스트가 아니다. 필드 출처·분기·권한·완료를 연결해야 하므로 ID 복사만으로 충족되지 않는 공통 기준과도 맞는다. 다만 최종 산출물의 중립성을 명시하는 수정과 화면 역할의 좁은 모호성 해소를 권고한다.

## 수정 권고

1. **최종 형식 중립성 — R02/R12/R15/R17/R19/R21/R28/R30/R35–R42.** 증거표의 `enum`, `ExistingModel`, `ExactlyOne Create`, `Skip`, `Required`, `Unique`, `producer`, `source-backed`는 공개된 사업 의미의 평가자용 약어로 읽을 수 있지만 RSPDL 철자·구문을 요구하는 것으로 오독할 여지가 있다. 증거표 앞에 다음을 명시할 것을 권고한다: “아래 기술 용어는 의미의 약칭이다. 별도 닫힌 선택 집합, 직접 전달한 기존 레코드, 레코드 한 개 생성/미생성, 각 출력에서 대상 정확히 하나, 성공 조회의 필드 확보를 동등한 한국어·표로 표현하면 충족이다. 최종 명세에 RSPDL 구문을 요구하지 않는다.” 기존 ‘다른 표현 허용’ 원칙을 실제 행 해석에도 적용하는 보강이다.
2. **상충하는 가상 형식 예외 — 전체 42개.** 허용 표현의 “평가 환경이 RSPDL 산출물을 요구한다면…”은 이번 B/C 공통 최종 한국어 명세 계약과 맞지 않는 가정이다. 해당 예외를 삭제하고 “최종 한국어 명세만 채점하며 중간 RSPDL·compiler 로그로 누락을 보충하거나 가점하지 않는다”로 바꾼다. 공통 실행·평가 지시는 이미 이 원칙을 올바르게 고정한다.
3. **공유 완료 화면의 알림함 경로 — R13/R14/R38.** 공개 R14는 업무 완료를 두 역할에 열면서 교육담당 전용 알림함으로 돌아가는 경로를 함께 적는다. 일반적인 역할 제한을 적용하면 교육담당에게만 이 경로를 제공하면 되지만 그 적용을 공개 입력에 한 문장으로 명확히 하는 편이 좋다: “업무 완료의 알림함 복귀 경로는 교육담당에게 제공하며, 감사열람자는 발급내역으로 돌아간다.” 감사열람자의 조회 행동 허용과 화면 접근 제한은 별도 계약으로 유지한다. 이 정리 전에는 역할 제한을 지킨 후보를 숨은 화면 정책으로 감점하지 않는다.
4. **합성 값은 출력 양식이 아님 — 여정 1–3, R04–R10/R20/R21/R24/R26/R30/R33.** 기대 literal은 공개 출처·문구 계약을 사람이 대입해 확인하는 예시다. 후보가 `CERT-104-A` 등 비공개 예시 자체를 최종 명세에 적을 필요가 없다는 문장을 보강하면 입력을 그대로 베끼는 채점으로 오해하지 않는다. 날짜/식별자 일부만 제시한 과거 기존 레코드는 완전 실행 fixture가 아니며 그 예시의 미기재 필드를 후보 누락으로 세지 않는다.

## 세 여정의 값과 경계 확인

- **수료 확인부터 최초 문서와 전달 접수까지:** `보안 기초 수료 확인`, `김다온님 / 보안 기초 / CERT-104-A`, `[수료 문서 안내] 김다온님, 문서 CERT-104-A가 준비되었습니다.`는 R20/R21/R30에서 정확히 도출된다. 외부 알림 사건을 발급 자동 결과로 만들지 않는다. 두 완료의 재조회도 공개 계약과 같다.
- **이름 정정, 조회 복구, 감사 열람:** 수정 표시이름 `김다온서`는 요청에서, 교육명은 원문서에서 온다. 당일 요청/희망처리일은 허용된다. 보류 후 외부 승인을 별도 호출에 제공하므로 자동 상태 변경을 요구하지 않는다. 시간초과/없음은 같은 조회로 복구하며 감사의 생성 금지를 별도로 확인한다.
- **미발급과 생략을 끝까지 빠뜨리지 않기:** 각 호출의 결정과 기존 레코드를 명시해 미생성 분기에서 자료가 생긴다고 가정하지 않는다. 세 종류의 같은 날짜는 모두 공개 R11의 유효 경계다. 별도 과거 문서/요청/알림은 공개된 기존 입력 계약에 맞는 읽기 예시이며 숨은 생성 행동을 추가하는 요구가 아니다. 실패·보류로 완료 필드를 확보했다는 근거를 인정하지 않는 것도 공개 계약과 같다.

## 지원 한계와 채점 중립성

`WORKFLOW-U001`의 조건부 workflow 미증명과 외부 typed 기존 레코드/초기 데이터/조회가 전역 `DATA-001/002` 생산자로 통합되지 않는 한계가 명시되어 있다. clean compile을 합격 조건으로 삼거나 가짜 외부 레코드 생성 화면을 요구하지 않아야 한다. 이 한계를 근거로 필드 출처나 재조회 의미를 지우는 것도 허용하지 않는다. 실행 시 도착·저장·메일·중복방지·입력 묶음 일치를 compiler가 증명한다는 요구는 없다.

공통 지시는 B/C 최종 한국어 산출물만 보고 평가하며 중간 RSPDL로 가점하지 않는다. 동일한 표현·의미 허용 원칙을 위 권고 1–2처럼 E02 rubric에도 직접 고정하면 더 일관된다. 실제 실행 전의 설계 검토이므로 평가자 간 일치도, 생성 모델이 실수하는 빈도, RSPDL 개선 효과는 아직 판단하지 않는다.
