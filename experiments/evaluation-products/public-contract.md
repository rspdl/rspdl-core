# 두 실험군에 공통으로 주는 산출물과 평가 기준

주어진 제품 전체를 구현 담당자가 읽을 수 있는 **한국어 제품 명세 하나**로 정리한다. 실제 프로그램·테스트 코드·실행 결과는 제출하지 않는다. 제품 입력에 있는 요구를 보존하며 모호한 부분을 임의의 업무 정책으로 채우지 않는다.

## 최종 명세에 포함할 내용

1. 제품 목적, 사용자 역할, 업무 시작·완료 범위, 외부에서 주어지는 정보.
2. 데이터별 필드·타입·필수 여부·날짜 제약과 관계. 데이터와 필드가 최초에 어디서 생기는지.
3. 화면·입력·버튼·연결 행동. 같은 행동이 여러 화면에 있으면 각 위치의 결과 경로.
4. 행동별 입력, 주체, 조건, 허용·금지·실제 시도, 생성·조회·수정·삭제되는 대상과 값의 출처.
5. 정상·실패·시간 초과·취소 등 **입력에 요구된** 결과와 복구 경로. 요구하지 않은 결과 종류를 무조건 추가하지 않는다.
6. 전체 업무의 진행과 완료 조건. 다른 진입 경로와 복구 이후에도 필요한 데이터가 확보되는 이유.
7. 요구사항 ID별로 이를 구현할 명세의 절·표 행을 연결한 추적표. 모순·미해결 항목·외부 구현 책임을 별도 기록한다.

위 항목은 문서 구성 안내다. 실제 필수 기능과 범위는 해당 제품 입력으로 결정한다. 절 이름·모델 이름·문장 표현은 바꿔도 의미가 같으면 허용한다. 입력에서 구별한 데이터·행동·주체·조건을 합치거나 생략해서 의미가 달라지면 안 된다.

입력을 순서대로 옮기는 데 그치지 않고 다음 연결을 한곳에서 검토할 수 있게 정리한다. 표나 동등한 구조를 사용하되 별도 실행 언어나 JSON 형식은 요구하지 않는다.

- **데이터 생애 표:** 자료·필드, 최초 출처, 생성/변경/조회/삭제 행동, 소비 화면·행동. 해당하지 않는 칸은 해당 없음으로 표시한다.
- **행동별 계약 표:** 입력·주체·조건·효과·결과별 후속 경로. 여러 요구사항에 흩어진 내용을 해당 행동 아래 모은다.
- **화면 연결 표:** 화면, 구별 가능한 입력·조회 영역·버튼 식별자, 연결 행동, 결과별 도착/제자리 처리·복구. 입력에 없는 버튼을 임의로 만들 필요는 없다.

이 구조는 주어진 업무 의도가 어떻게 연결되는지 확인하기 위한 공통 제출 형식이다. 표가 있다는 사실만 채점하지 않으며, 새 업무 정책이나 숨은 채점 항목을 추가하지 않는다. 같은 내용을 정확히 표현했다면 인위적으로 감점하지 않는다.

## 평가 기준

각 요구사항을 다음과 같이 판정한다.

| 판정 | 기준 |
| --- | --- |
| 충족 | 필요한 주체·조건·효과·출처·연결이 명세에 명확히 있고, 다른 부분과 모순되지 않는다. |
| 위반 | 내용이 없거나, 틀리거나, 서로 모순되거나, 원래 요구를 바꾸는 임의의 조건·자동화가 추가됐다. |
| 판정 보류 | 입력 또는 증거의 해석에 실제 쟁점이 있어 평가자가 단정할 수 없다. 근거와 쟁점을 기록한다. |

“요구사항을 준수한다”는 선언이나 추적표에 ID를 나열한 것만으로 충족되지 않는다. 조건을 검사하는 화면에서 우회 가능한 다른 버튼을 열어 놓았다면 관련 요구는 위반이다. 정상 사용까지 모두 금지하는 명세도 충족이 아니다.

중요도는 실패의 영향 설명에 사용하며 가중 점수는 주지 않는다. 모든 요구사항은 같은 분모에 들어간다. 제품 전체를 읽고 요구사항별로 평가하며 대표 여정만 맞았다고 나머지를 통과시키지 않는다.

문법 통과·타입 검사·의존성 검사를 실제 저장이나 업무 실행의 성공 보장으로 표현하지 않는다. 도구가 검사하지 못하는 의미를 명세에 정확히 남기는 것은 가능하지만, 도구가 검증했다고 주장하는 것은 별도로 평가한다.
